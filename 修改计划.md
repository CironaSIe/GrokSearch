## 二、各模块设计

### 2.1 `specialists/__init__.py`

```python
from enum import StrEnum
from abc import ABC, abstractmethod
from urllib.parse import urlparse
import httpx


class SourceType(StrEnum):
    GITHUB_ISSUE = "github_issue"
    GITHUB_PULL = "github_pull"
    ARXIV = "arxiv"
    WIKIPEDIA = "wikipedia"
    HACKER_NEWS = "hacker_news"


GLOBAL_UA = "GrokSearch/1.0 (https://github.com/GuDaStudio/GrokSearch)"


class SourceExtractor(ABC):
    """Extractor 实例在 router 中共享。match() 不可变，fetch_render() 的 client 由 router 管理。"""

    @abstractmethod
    def match(self, url: str) -> bool:
        """同步 URL 模式匹配（正则/字符串），不做网络请求。必须是无副作用的纯函数。"""
        ...

    @abstractmethod
    def kind(self) -> SourceType:
        ...

    @abstractmethod
    async def fetch_render(self, client: httpx.AsyncClient, url: str) -> str | None:
        """用传入的 client 请求 API，返回结构化 Markdown。失败返回 None。"""
        ...


class SourceRouter:
    def __init__(self, github_token: str | None = None,
                 http_proxy: str | None = None,
                 https_proxy: str | None = None):
        from .github import GithubIssueExtractor, GithubPrExtractor
        from .arxiv import ArxivExtractor
        from .wikipedia import WikipediaExtractor
        from .hackernews import HackerNewsExtractor

        self._extractors: list[SourceExtractor] = [
            GithubIssueExtractor(github_token),
            GithubPrExtractor(github_token),
            ArxivExtractor(),
            WikipediaExtractor(),
            HackerNewsExtractor(),
        ]
        self._http_proxy = http_proxy
        self._https_proxy = https_proxy

    def _clean_url(self, url: str) -> str | None:
        """剥离 fragment（#锚点），保留 query 参数。无效 scheme 返回 None。"""
        parsed = urlparse(url)
        if parsed.scheme not in ("http", "https"):
            return None
        cleaned = f"{parsed.scheme}://{parsed.netloc}{parsed.path}"
        if parsed.query:
            cleaned += f"?{parsed.query}"
        return cleaned

    def resolve(self, url: str) -> SourceExtractor | None:
        cleaned = self._clean_url(url)
        if cleaned is None:
            return None
        for ex in self._extractors:
            if ex.match(cleaned):
                return ex
        return None

    async def fetch(self, url: str, timeout: int | float) -> str | None:
        cleaned = self._clean_url(url)
        if cleaned is None:
            return None
        extractor = self.resolve(url)
        if extractor is None:
            return None
        try:
            proxies = {}
            if self._http_proxy:
                proxies["http://"] = self._http_proxy
            if self._https_proxy:
                proxies["https://"] = self._https_proxy
            if not proxies:
                proxies = None

            async with httpx.AsyncClient(
                timeout=timeout,
                proxies=proxies,
                follow_redirects=True,
            ) as client:
                content = await extractor.fetch_render(client, cleaned)
                if content and content.strip():
                    return content
        except Exception:
            pass
        return None
```

**关键设计点：**

- `match()` 是纯函数，无副作用、无状态——同一 extractor 实例可被多请求共享
- URL 标准化只剥离 fragment（`#锚点`），保留 query（`?id=123`）——HN 的 item ID 在 query 中，不可丢失
- `_clean_url()` 被 `resolve()` 和 `fetch()` 共用，保证 `match()` 和 `fetch_render()` 看到相同格式的 URL
- proxy 分离 HTTP/HTTPS，各自独立配置。`None` 时不传入，不影响其他 provider
- `fetch()` 内部管理 client 生命周期，extractor 不接触 httpx 配置

### 2.2 `specialists/github.py` — GitHub Issues & Pulls

**URL 模式：**
- Issues: `https://github.com/{owner}/{repo}/issues/{number}`
- Pulls: `https://github.com/{owner}/{repo}/pull/{number}`
- 也匹配 `https://github.com/{owner}/{repo}/discussions/{number}`？（暂不，后续可加）

**API：** `GET https://api.github.com/repos/{owner}/{repo}/issues/{number}`

**Headers：** `Accept: application/vnd.github.v3+json`，`Authorization: Bearer {token}`（可选）

**限频：** 有 token → 5000/h，无 token → 60/h

**渲染结构：**
```markdown
# #{number} {title}
> **状态：** {state} | **作者：** {user.login} | **创建：** {created_at}
> **标签：** {labels}

{body}

---

**评论：**
> **@{user.login}** 于 {created_at}：
{body}
```

**匹配正则：**
```python
_PATTERN = re.compile(r"^https://github\.com/([^/]+)/([^/]+)/(issues|pull)/(\d+)$")
```

**返回值：** 提取 `match.groups()` 在 `match()` 中不存储状态，`fetch_render()` 中重解析 URL。

```python
class GithubIssueExtractor(SourceExtractor):
    _pattern = re.compile(r"^https://github\.com/([^/]+)/([^/]+)/issues/(\d+)$")

    def __init__(self, token: str | None = None):
        self._token = token

    def match(self, url: str) -> bool:
        return bool(self._pattern.match(url))

    def kind(self) -> SourceType:
        return SourceType.GITHUB_ISSUE

    async def fetch_render(self, client: httpx.AsyncClient, url: str) -> str | None:
        m = self._pattern.match(url)
        if not m:
            return None
        owner, repo, _, num = m.groups()
        api_url = f"https://api.github.com/repos/{owner}/{repo}/issues/{num}"
        headers = {"Accept": "application/vnd.github.v3+json"}
        if self._token:
            headers["Authorization"] = f"Bearer {self._token}"

        resp = await client.get(api_url, headers=headers)
        if resp.status_code != 200:
            return None
        data = resp.json()

        # 渲染
        lines = [
            f"# #{data['number']} {data['title']}",
            f"> **状态：** {data['state']} | **作者：** {data['user']['login']} | **创建：** {data.get('created_at', '')[:10]}",
        ]
        if data.get('labels'):
            labels = ', '.join(l['name'] for l in data['labels'])
            lines.append(f"> **标签：** {labels}")
        lines.append("")
        body = data.get('body', '')
        if body:
            lines.append(body)
            lines.append("")

        # 获取前 5 条评论
        comments_url = data.get('comments_url', '')
        if comments_url:
            # comments_url is already the full API URL
            headers["Accept"] = "application/vnd.github.v3+json"
            resp2 = await client.get(comments_url, headers=headers)
            if resp2.status_code == 200:
                comments = resp2.json()
                if comments:
                    lines.append("---\n")
                    lines.append("**评论：**\n")
                    for c in comments[:5]:
                        lines.append(f"> **@{c['user']['login']}** 于 {c.get('created_at', '')[:10]}：")
                        lines.append(f"> {c.get('body', '')}")
                        lines.append("")

        return "\n".join(lines)
```

### 2.3 `specialists/arxiv.py` — arXiv 论文

**URL 模式：**
- `https://arxiv.org/abs/{id}`
- `https://arxiv.org/pdf/{id}`
- `https://arxiv.org/abs/{id}v{N}`（带版本号）
- `http://arxiv.org/abs/{id}`（HTTP 也 ok）

**API：** `GET http://export.arxiv.org/api/query?id_list={id}`

**注意：** arXiv API 是 **HTTP** 不是 HTTPS！使用 `follow_redirects=True`。

**限频：** 1 请求/3 秒，单连接

**渲染结构：**
```markdown
# {title}

**作者：** {authors}
**分类：** {categories}
**提交日期：** {published}
**DOI：** {doi}
**摘要链接：** {arxiv_url}

{abstract}

---
*更多信息：[arXiv.org]({abs_url})*
```

**匹配正则：**
```python
_PATTERN = re.compile(r"^https?://arxiv\.org/(?:abs|pdf)/(\d+\.\d+)(?:v\d+)?$")
```

注意从 `/pdf/{id}` 和 `/abs/{id}` 中提取的 ID 是相同的。

### 2.4 `specialists/wikipedia.py` — Wikipedia 摘要

**URL 模式：**
- `https://{lang}.wikipedia.org/wiki/{title}`
- `http://{lang}.wikipedia.org/wiki/{title}`

**API：** `GET https://{lang}.wikipedia.org/api/rest_v1/page/summary/{title}`

**Headers：** 必须设 User-Agent（否则只有 10/min），建议 `GrokSearch/1.0 (https://github.com/GuDaStudio/GrokSearch)`

**限频：** 设 UA → 200/min；不设 UA → 10/min

**渲染结构：**
```markdown
# {title}

{extract}

---
*来源：[Wikipedia]({content_urls.desktop.page})*
```

**匹配正则：**
```python
_PATTERN = re.compile(r"^https?://([a-z-]+)\.wikipedia\.org/wiki/(.+)$")
```

### 2.5 `specialists/hackernews.py` — Hacker News

**URL 模式：**
- `https://news.ycombinator.com/item?id={id}`
- `https://news.ycombinator.com/item?id={id}&p={page}`

**API：** `GET https://hacker-news.firebaseio.com/v0/item/{id}.json`

**无需认证，无条件限制（Firebase 托管）。**

**渲染结构：**
```markdown
# {title}

**作者：** {by} | **分数：** {score} | **评论：** {descendants}

{text}

---
*来源：[Hacker News](https://news.ycombinator.com/item?id={id})*
```

**HTML 处理：** `text` 字段是 HTML，需要清洗：
1. `<p>` 替换为 `\n\n`（段落换行）
2. `&amp;` / `&lt;` / `&gt;` 等 HTML 实体用 `html.unescape()` 解码
3. 其余 tags 用 `re.sub(r'<[^>]+>', '', text)` 粗略剥离
4. 不做完整 HTML 解析，保持轻量

**匹配正则：**
```python
_PATTERN = re.compile(r"^https://news\.ycombinator\.com/item\?id=(\d+)(?:&.*)?$")
```

注意：`text` 字段是 HTML。需要清理 HTML tags 或用简单 regex 提取纯文本？直接用 `re.sub(r'<[^>]+>', '', text)` 粗略清洗即可，不做完整 HTML 解析以保持轻量。

## 四、fetch provider 选择 + Python 原生抓取

### 7.1 设计背景

当前 `web_fetch` 硬编码 Tavily → Firecrawl → Grok 顺序，LLM caller 无法选择后端。实际上各 provider 有不同优势：

| provider | 优势 | 弱势 | 成本 |
|----------|------|------|------|
| Python (httpx+trafilatura) | 零成本，快速，适合静态 HTML 页面 | 不支持 JS 渲染/反爬 | 免费 |
| Tavily extract | 提取质量好，处理复杂页面 | 付费，有配额 | 付费 |
| Firecrawl scrape | 支持 JS 渲染，fetch-first | 付费 | 付费 |
| Grok fetch | LLM 理解语义，能处理反爬 | 慢，消耗 AI 配额 | 低价 |

LLM 作为调用方应能按需选择。

### 7.2 `web_fetch` 签名变更

```python
async def web_fetch(
    url: str,
    timeout: int = 0,
    provider: str = "auto",   # 新增
    ctx: Context = None,
) -> str:
```

`provider` 可选值：`"auto"` | `"python"` | `"tavily"` | `"firecrawl"` | `"grok"`

### 7.3 选择逻辑

```python
_PROVIDER_PRIORITIES = {
    "auto":     ["python", "tavily", "firecrawl", "grok"],
    "python":   ["python"],
    "tavily":   ["tavily"],
    "firecrawl":["firecrawl"],
    "grok":     ["grok"],
}

async def web_fetch(url, timeout=0, provider="auto", ctx=None):
    ft = timeout if timeout > 0 else config.fetch_timeout_seconds
    await log_info(ctx, f"Begin Fetch: {url}", config.debug_enabled)

    # Stage 0: Specialist（always tried when URL matches）
    if source_router:
        result = await source_router.fetch(url, ft)
        if result:
            await log_info(ctx, f"Fetch Finished ({result[1].value})!", config.debug_enabled)
            return result[0]

    # Stage 1-N: Generic backends in provider order
    for name in _PROVIDER_PRIORITIES.get(provider, ["python"]):
        result = await _try_fetch_backend(name, url, ft, ctx)
        if result:
            await log_info(ctx, f"Fetch Finished ({name})!", config.debug_enabled)
            return result

    # All failed
    await log_info(ctx, "Fetch Failed!", config.debug_enabled)
    return "提取失败: 所有提取服务均未能获取内容"
```

### 7.4 Python 原生抓取实现

新增 `_try_fetch_backend("python", ...)`，内部使用 `httpx.AsyncClient` + `trafilatura`：

```python
async def _try_fetch_python(url: str, timeout: int) -> str | None:
    """httpx GET + trafilatura 提取正文→Markdown。失败返回 None。"""
    try:
        import httpx
        from trafilatura import extract
    except ImportError:
        return None  # 未安装 trafilatura，跳过

    try:
        async with httpx.AsyncClient(
            timeout=timeout,
            follow_redirects=True,
            headers={"User-Agent": "Mozilla/5.0 (compatible; GrokSearch/1.0; +https://github.com/GuDaStudio/GrokSearch)"},
        ) as client:
            resp = await client.get(url)
            resp.raise_for_status()

            if "text/html" not in resp.headers.get("content-type", ""):
                # 非 HTML 内容（PDF/JSON等），跳过交给下游
                return None

            md = extract(
                resp.text,
                output_format="markdown",
                include_comments=False,
                fast=True,
            )
            return md if md and md.strip() else None

    except Exception:
        return None
```

**软依赖：** trafilatura 不是必装包。`try: import trafilatura` 失败时直接返回 None，跳到下一 backend。

**为什么不自己写 HTML→Markdown？** trafilatura 在 F1 基准测试中达到 ~0.95，优于 readability-lxml 和 newspaper4k。自行实现的 regex/BeautifulSoup 方案精度和健壮性都远不如。

### 7.5 `_try_fetch_backend` 调度器

```python
_BACKEND_DISPATCH = {
    "python": _try_fetch_python,
    "tavily": _call_tavily_extract,
    "firecrawl": _call_firecrawl_scrape,
    "grok": _try_fetch_grok,  # 从现有逻辑提取
}

async def _try_fetch_backend(name: str, url: str, timeout: int, ctx) -> str | None:
    fn = _BACKEND_DISPATCH.get(name)
    if fn is None:
        return None
    try:
        return await fn(url, timeout)
    except Exception:
        return None
```

`_call_tavily_extract` 和 `_call_firecrawl_scrape` 已存在且返回 `str | None`。`_try_fetch_grok` 从现有 `web_fetch` 的 Grok fallback 逻辑提取为一个独立函数。

### 7.6 Grok fetch 提取为独立函数

```python
async def _try_fetch_grok(url: str, timeout: int) -> str | None:
    if not config.grok_fetch_fallback_enabled:
        return None
    try:
        api_url = config.grok_api_url
        api_key = config.grok_api_key
    except ValueError:
        return None
    provider = GrokSearchProvider(api_url, api_key, config.grok_model, timeout=timeout)
    return await provider.fetch(url, None)
```

### 7.7 向后兼容

`provider="auto"` 是默认值，行为与当前相同，但 fallback 序列变为 `python → tavily → firecrawl → grok`（新增 python 步骤）。仅当 trafilatura 未安装时 python 步骤被跳过，此时行为完全等同于当前。

## 五、Proxy 处理逻辑

`SPECIALIST_HTTP_PROXY` / `SPECIALIST_HTTPS_PROXY` 环境变量控制：

- 仅作用于 specialist 创建的 `httpx.AsyncClient`，不影响其他 provider
- 格式：`http://127.0.0.1:7890`
- 两变量独立设置。Router 在构造 client 时合并为 dict：`{"http://": http_proxy, "https://": https_proxy}`
- 都未配置时不传 proxy 参数，client 走直连

**为什么独立变量？** 因为 `HTTP_PROXY` / `HTTPS_PROXY` 通常被 Tavily、Firecrawl、Grok 等已有 provider 的系统 HTTP 库共用。加独立变量避免干扰，也允许用户为 specialist 走不同代理（如直连 Wikipedia 但不走 GitHub）。

## 六、错误处理矩阵

| 异常场景 | Extractor 返回 | Router 行为 | 最终 |
|---------|---------------|------------|------|
| URL 不匹配任何 extractor | match() → False | resolve → None, fetch → None | → Tavily |
| API 超时 | httpx 抛异常 | except → None | → Tavily |
| API 返回非 200 | `if resp.status_code != 200: return None` | → None | → Tavily |
| API 返回空内容 | fetch_render → "" | `content.strip()` → False | → Tavily |
| 网络错误（DNS/连接被拒） | httpx 抛异常 | except → None | → Tavily |
| GitHub 限频 403/429 | `if resp... != 200: return None` | → None | → Tavily |
| Wikipedia User-Agent 不足导致 429 | same | → None | → Tavily |
| router 初始化失败（ImportError） | — | `source_router = None` | → Tavily |
| extractor 代码 bug（意外异常） | 抛出 | except → None | → Tavily |

**结论：** 任何异常都不会影响下游 Tavily/Firecrawl/Grok 链路。
